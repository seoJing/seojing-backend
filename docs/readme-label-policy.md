# 순차 독해 라벨 정책과 검수 자료

2026-10-04. 아래 정책은 구현·평가용 초안이다. 사람이 검토한 정답으로 승인됐다는 뜻이 아니다. 현재 [8개 합성 prefix 사례](../test/fixtures/readme/reader-prefix-cases.json)는 `provisional_agent_authored`, `human_reviewed=false`다. 이미 개발 실험에 사용했으므로 최종 비공개 평가셋으로 재사용하지 않는다.

검토자는 **현재 위치까지의 원문, 질문의 대상 경험, 충분한 설명 조건**만 본다. 문서 뒤의 정답을 과거 시점 라벨에 쓰지 않는다. 주장하는 사람이 실제로 일을 했는지와 문서가 그 질문을 설명하는지는 구분한다.

| 라벨      | 조건                                                  | 반례                                           |
| --------- | ----------------------------------------------------- | ---------------------------------------------- |
| complete  | 같은 경험이며 질문의 충족 조건 전체를 설명            | 본인 역할 질문에 팀 전체 성과만 나옴           |
| partial   | 질문과 관련된 설명은 있으나 충족 조건 일부가 남음     | 변경 후 수치만 있고 비교 전 값/조건이 없음     |
| conflict  | 이전 답변을 부정·정정하거나 같은 사실에서 모순이 생김 | 무관한 경험에서 다른 수치가 나옴               |
| unrelated | 다른 경험 또는 질문과 무관한 설명                     | 키워드가 같다고 답으로 연결                    |
| unknown   | 경험 연결·의미·입력이 불충분해 관계를 판정할 수 없음  | 모델이 모른다는 이유로 문서의 설명 부족을 확정 |

`scope_id`는 문단/제목 범위일 뿐 같은 경험을 인증하지 않는다. 부정문도 유효한 설명일 수 있으므로 무조건 무관/부족으로 표시하지 않는다. 역할을 하지 않았다는 설명으로 특정 사실 질문은 끝날 수 있지만, 다른 실제 담당 업무를 묻는 질문에는 답이 남을 수 있다. 이런 사례는 질문 정의부터 검토한다.

검수 기록에는 case_id, 정책 버전, 선택 라벨 또는 허용 라벨 집합, 인용, 짧은 판단 이유, 실제 검수자 ID를 남긴다. 애매한 경우 합의되지 않은 단일 라벨을 강요하지 말고 재작성/보류한다. Codex의 정답 초안·높은 확신·다른 에이전트의 코드 리뷰를 사람 승인으로 기록하지 않는다.

다음 데이터 확장은 본인/팀, 실제/계획, 부정 양방향, 같은/다른 경험, 부분/충분 답, 앞선 역할 기억, 후속 정정, 미래 문장 교체의 불변성을 포함한다. 기본 경험·공고·템플릿 계열을 묶어 train/dev/calibration/test를 분리한다. 먼저 약 30개 기준 사례의 사람 검수로 정책을 고정하고, 그 뒤 생성 규모와 학습 단계를 확장한다. 이 수량은 작업 계획이며 현재 검수 완료 수량은 0이다.

현재 서비스 가중치는 기본 모델이며, 이 자료나 사용자 원문은 자동 학습에 넣지 않는다. `train.py`는 사람이 승인한 학습 데이터와 합성 smoke 모드를 구분한다. 파인튜닝·보정·승격은 별도 측정과 검수 후 진행한다.
