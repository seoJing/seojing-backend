# README Lab · Jev / local Laya + Codex CLI · v1/v2

2026-10-04. New additive contract for `/readme/lab`; existing `/readme/preview`, `/readme/analyze`, and public contest demonstration remain separate. Implementation is not deployment. The authoritative types are `src/services/readme-lab/contracts.ts`. UI ownership is Claude; model, state, transport, and validation ownership is Codex.

## Runtime split

### Inquiry focus reader (2026-10-07, opt-in)

The route factory now accepts `README_LAB_ENGINE=jev-focus` and opens the protected focus worker. It still returns `generation.engine=jev` with `generation.policy_version=readme-focus-v1`. The existing `jev` setting continues using `readme-prefix-v2`; omitted engine selection still uses Laya. No production environment is changed by this implementation.

Focus requires the same explicit `consent_version=readme-jev-v1`, server-only `TYPESAFE_API_KEY`, and Codex CLI setup. `README_JEV_PYTHON` selects the shared Python executable. An optional **`README_FOCUS_JEV_SCRIPT`** selects the focus worker; the legacy `README_JEV_SCRIPT` is deliberately ignored in this mode because the worker protocols differ. The default focus worker is `src/services/readme-lab/python/jev_focus_runtime.py` relative to the backend working directory.

The protected production launcher requires an absolute, release-pinned `README_FOCUS_JEV_SCRIPT` for `jev-focus`, or `README_JEV_SCRIPT` for `jev`. It rejects missing, relative, mixed-protocol and unknown configuration fields before starting the server. Keep credentials in the owner-only runtime file outside Git and preserve the previous config with its release for rollback.

The reader sends bounded working sets and retrieves earlier original passages to track one active inquiry, parked questions, later answers and corrections. It receives up to three main duties as background, not the per-requirement reading checklist. Deterministic `speech` codes require no extra model calls. Final Codex reporting still checks the full original document against the posting. Focus events and their exact source/transition invariants are defined in `focus-contract.ts`; transport seq/cursor/windows, authentication, ownership and failure semantics are unchanged. A final worker checkpoint and exact source binding are required before reporting.

For rollout, first verify the focus-capable frontend with this backend in a non-production environment, including consent, completion/report, reconnect, cancellation and partial failure. Release that consumer before switching the server setting. Selecting `jev` again restores the older reader for new jobs after a restart; runtime jobs are ephemeral, so restarts cannot preserve in-flight analyses. Deploying code, activating the policy and measuring public readback are separate steps. Do not configure a new server against a consumer that does not recognize `readme-focus-v1`.

### Existing prefix modes

- The acknowledged Jev serving contract is implemented after Claude ACK `96385c`. Set `README_LAB_ENGINE=jev` explicitly; an omitted value still selects legacy Laya, and an unknown value is rejected. Jev returns `generation.engine=jev` and fixed metadata `{model:jev-1.13.0, provider:typesafe, execution:remote, calibrated_for_readme:false}` from the initial job response. It reads the complete already-read prefix, generated job conditions and current questions remotely through Typesafe, checking only personal role and measured-improvement basis. It can emit partial/resolved/reopened states; these are uncalibrated model judgments, not verified facts. Other facets are reviewed by Codex at the end. There is no Laya fallback after a Jev failure. This implementation is not a deployment or a general accuracy approval.
- New real preparations compile `job.reader_profile` and use `generation.policy_version=readme-prefix-v2`. Old authored v1 fixtures and jobs without a profile keep v1 behavior. The accepted v2 contract and measured limitations are in [readme-reader-v2.md](readme-reader-v2.md).
- Local Laya receives only the current/past prefix. V2 keeps all raw read units in an ephemeral ledger, checks actor/performed-vs-planned/facets and earlier questions independently of generic concreteness, and supplies sourced job-specific trigger/sufficiency conditions. It tries all same-scope past context first; only an actual tokenizer budget failure causes a compact retry and context-limited abstention. Scope is a conservative structural boundary, not semantic proof of one experience.
- Codex CLI extracts every stated duty, required and preferred item (bounded at 64 total entries), preserves employment/application context as `other`, compiles conditional reading checks in batches of eight (at most two concurrent CLI calls), and audits whole-posting coverage and meaning **before confirmation**. After reading it receives **all extracted resume sentences**, source-backed criteria, notes and the ledger for an explicit final source review. V2 validates exact quote offsets and audits claim/source meaning, with at most two draft attempts. It cannot rewrite earlier question states. V1 retains note-linked source packing for reproducibility. The executable uses the Mac mini's existing ChatGPT login; no API key is used. Invocation is local, inference is cloud-based; the uploaded binary file is not sent to Codex.
- Base multilingual Laya is not resume-fine-tuned or calibrated. Every note is `review_required: true`. Confidence is an internal conservative gate, not an accuracy score. Answer candidates stay `held`; there is deliberately no automatic `resolved` status before task-specific validation. Reports cannot silently change this question ledger.

## HTTP and frontend flow

All paths below are relative to backend `/readme/lab`. A frontend same-origin proxy should map `/api/readme/lab/*` and preserve Authorization, method, body, response status and no-store/noindex headers. Do not expose an invitation in bundled JS. Do not index the frontend page or add it to sitemap/navigation.

1. `POST /session` `{invite_code, cloud_consent:true, consent_version:"readme-jev-v1"}` → `{access_token, expires_at}`. Jev requires both true consent and this exact version; missing or stale version returns `cloud_consent_required` before model processing. Laya accepts the version as an optional field for schema compatibility, but its own disclosure must describe local Laya processing. The Jev page discloses that job-derived requirements/conditions, every already-read resume sentence (including name/contact lines), and questions go to Typesafe Jev; job text goes to OpenAI Codex for preparation, and all extracted resume sentences and notes go to Codex for final source review. Neither model receives the uploaded binary file itself. Freeze the actual page consent at deployment and change both version and page text together after launch. Code length at least 16; configure a different random code for each person. All following calls require `Authorization: Bearer <access_token>`.
2. `POST /prepare` `{job_text,resume_filename,resume_media_type,resume_base64}` → 202 `PrepareView`. Poll `GET /prepare/:id` every second until `ready`/`failed`/`cancelled`. States: queued → extracting → analyzing_job → ready. No reading starts here.
3. Display `job.requirements` with their literal `quote`, and `document.blocks` in order. Require confirmation of both job extraction and document omissions/order. Changes to any input require DELETE of old preparation and another prepare request. `POST /jobs` `{prepare_id,input_hash,confirmed:true}` → 202 `JobView`. The same preparation starts at most one job; repeated start returns that job.
4. Poll `GET /jobs/:id?after_seq=0`. Events have contiguous sequence numbers starting at 1; next request uses `next_seq`. Repeating a cursor returns the same recorded events plus any newly appended ones. No consumptive queue. Status: queued → reading → reporting → completed; failed/cancelled are terminal and preserve prior events. Continue polling while the UI's animation is paused. Reading and display playback are independent.
5. `DELETE /jobs/:id` cancels computation; `DELETE /prepare/:id` discards that preparation and cancels its running job. No polling for 60 seconds cancels pending work. Session/data TTL is two hours, non-durable; restart expires everything. Resume a page refresh with the bearer token and job ID in sessionStorage and fetch from cursor 0; never put raw document data in persistent browser storage. Get the saved preparation to reconstruct the document.

`browser-client.ts` supplies fetch calls, an abortable polling generator, and the event reducer with cursor-gap detection. Copy that file and `contracts.ts` together into the frontend when its writer is ready; its default base is `/api/readme/lab`. After presenting the Jev disclosure and receiving consent, use `session(code, true, signal, "readme-jev-v1")`; the client never invents a consent version for older Laya callers. Claude's page has its own synchronized HTTP client. Call `start` only after both checkboxes are checked. Aborting local polling does not instantly cancel server work; call `cancel` for an explicit stop.

`watchJob(id, signal, onConnection?)` optionally reports `{status, attempt, retry_in_ms, error}`; connection status is connected/reconnecting/disconnected, separate from the server job status. GET polling retries transient network/408/429/500/502/503/504/520–527 failures at most three times, waiting 1/2/4 seconds; each poll has a 10-second timeout. It retains the last cursor and notes, resets the retry count after recovery, and honors abort during both fetch and delay. HTML proxy failures map to `LabClientError("upstream_unavailable", status)`. Expired/auth errors, malformed successful JSON, cursor gaps, and POST/DELETE mutations are not retried. After exhaustion retain the partial view and offer reconnect; do not synthesize a server `failed` event. Real browser scheduling/background suspension can exceed the server idle TTL, so an eventual expired/cancelled response still takes precedence.

## Document, notes, report

- Render **block.text**, preserving its whitespace. Never render the uploaded HTML or concatenate sentence texts. TXT/MD line order is retained, markdown heading/bullet syntax remains in text. DOCX uses extracted heading/list/table row structure. PDF supplies flattened text and an explicit order/OCR warning. The input review is mandatory for every format.
- Units reference `block_id`, exact text, `order`, and zero-based UTF-16 `[start,end)` offsets into block.text. Emoji is not split between surrogate halves. Limits: 2 MB file, 24,000 extracted characters, 120 units, 10 PDF pages, 6,000 job characters. Excess documents fail explicitly; no silent truncation. Image-only/OCR documents fail for insufficient text.
- `window_started` identifies the next one-unit reading window; `note` adds a permanent semantic note; `window_completed` advances progress. `reading_completed` precedes Codex report synthesis; `report_completed` enables the wide report. Error events preserve partial notes without pretending there is a final report.
- Note kinds: question, evidence, hold, observation, and v2 resolves. Note `span` locates pen/highlight markup. `evidence_unit_ids` contains only already-read units; `requirement_ids` is always an array. V2 never emits an evidence card with an empty requirement list. `question_id` links notes. These are short observable review comments, not hidden chain of thought or a real recruiter's thoughts.
- V2 `question_updated` includes question_id, previous_status (null on creation), status, evidence_unit_ids, at_unit_id, state_version, and an immutable full `question` snapshot including label/facet/criterion. The browser reducer exposes `ReadingState.questions`, rejects version/state gaps, and ignores replayed event sequences. The first question's origin stays fixed; source-to-answer connectors use its unit_id and the transition's at_unit_id. V1 held must never be rendered as resolved.
- Low-confidence classifications and unchanged repeated questions produce no note. A unit completing without a note is not an endorsement or proof that nothing needs improvement. Laya base-model v2 candidates remain held. Jev can emit partial/resolved/reopened transitions; current evidence can be replaced while historical notes stay immutable. A diagnostic finding of excessive abstention is an open quality issue, not success.
- Hover a unit to highlight related notes; click pins. User inspection must not be overridden by new-event autoscroll. Keep the accumulated notes and annotations when toggling report/document modes.
- Report `items` have category explained/open/improve, text, reason, citations, note_ids, requirement_ids. In v2, literal source quotes are checked against the specified unit and offsets computed by the server. V2 can cite a passage with no public note (`note_ids=[]`) during final source review; linked notes must overlap its cited passages. `reason` labels this final review explicitly. User-facing prose excludes internal IDs/status codes. Explained means explained in the document, not verified competence. Selecting an item focuses the same centered document at its citation; restore report scroll/selection on return. `questions` comes from the reading ledger and `limitations` must be visible.

## Capacity and errors

One model task at a time, four total running/queued tasks, three preparations per invitation per UTC day. Quota is process-memory state and resets on restart; this is a limited acquaintances trial, not persistent billing/abuse protection. Sessions are isolated even if the same invite is reused. Authentication is required despite noindex; noindex alone is not access control.

A preparation attempt consumes quota once queued, including a later parser/model failure. Invalid HTTP bodies, missing authentication and a full queue do not consume it. Login attempts are capped at 10/IP/minute, authenticated requests at 180/session/minute, in addition to the host app's existing 120/IP/minute public guard. The frontend proxy must forward the trusted original Cloudflare client IP; otherwise all proxy users share that outer limit. Invalid JSON, oversized HTTP bodies and unsupported content types retain 400/413/415 (`invalid_input`, `request_too_large`, `unsupported_media_type`). Lab routes are hidden from public Swagger listings.

Errors are `{error:code}` with 400/401/404/409/410/413/422/429/503 as appropriate. Important codes: invite_invalid, cloud_consent_required, daily_limit_reached, queue_full, invalid_input, document_too_short, document_too_long, text_extraction_failed, document_resource_limit, prepare_input_changed, prepare_not_ready, confirmation_required, invalid_cursor, expired, cancelled, engine_timeout, engine_input_invalid, engine_output_invalid, engine_unavailable, engine_budget_exceeded. The last code identifies the per-document Jev limit (600 requests or 2M accumulated input tokens, checked between calls); preserve partial notes and request a shorter input rather than retrying the same document as if the provider were down. Extraction may also return existing upload validation codes. No synthetic success fallback. Failed CLI/report jobs retain their already-produced reading events.

## Setup and execution

For Jev, set `README_LAB_ENABLED=1`, `README_LAB_ENGINE=jev`, private `README_LAB_INVITES`, secret `TYPESAFE_API_KEY`, and absolute `README_JEV_PYTHON`, `README_JEV_SCRIPT`, `README_CODEX_BIN` paths appropriate to the release checkout. Jev uses stdlib Python and needs no Laya weights. The parent passes the key through the worker's stdin, never arguments or inherited provider environment. Store no credential values in source, board posts or release artifacts. Before publishing the page, verify the compiled build accepts the versioned consent and immediately labels POST jobs as Jev. Production restart, actual provider HTTP/browser smoke, and long-document capacity remain release gates; fake-model HTTP tests do not establish them.

The following setup is for the legacy local Laya mode only:

Model: `convaiinnovations/laya-multilingual`, revision `e4e9ddf21a7b1903b7acffd8814ad4307bf63a67`. SDK: 0.3.25, upstream source `8a976468b57c1b53541363dc86523263c9b68d34`. The published wheel omits `laya.backends`; install the pinned source as editable until that upstream packaging issue is fixed. Source/working-model hashes are recorded separately because the SDK normalizes tokenizer config for transformers 4.x. The runtime is offline and verifies working-model hashes at every load.

Run from repository root (Python 3.12):


The host account must already be authenticated. Never copy its auth file into source, browser, or a container image. Runtime configuration: `README_LAB_ENABLED=1`, `README_LAB_INVITES=<comma-separated private codes>`, optional `README_CODEX_BIN` (default `/opt/homebrew/bin/codex`), `README_CODEX_MODEL` (otherwise CLI default, reported honestly as `cli_default`), `README_LAYA_HOME`, `README_LAYA_SCRIPT`. Default working paths assume repository-root cwd; set explicit paths for another cwd. Keep the endpoint disabled until frontend consent, invite flow, proxy, and deployment checks are ready. No launchd/tunnel/deployment changes are included.

Codex runs in a fresh temporary directory, ephemeral session, read-only sandbox, with user config/rules/tools/plugins/browser/MCP discovery disabled and a credential allowlist environment. Uploaded content goes through stdin, not shell interpolation. ChatGPT authentication is enforced, history persistence is disabled, reasoning output is hidden, and SQLite/log directories are redirected into that same temporary directory. These per-invocation settings use the [official OpenAI configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference). The directory is removed even on failure. This is not a promise about the provider's cloud retention policy. Application logs must not include prompts, documents, model reasoning, invitation codes, or tokens.

Structured outputs and every quoted/cited reference are checked. V1 only receives already-linked requirements, enumerates note IDs and excludes explained without evidence notes. V2 can inspect the full bounded document after reading. Each observation first receives a separate audit using only its own quotations; the full-source audit then checks gaps, suggestions, source scope and redundant feedback. Every item must have exactly one audit result. A rejected or malformed draft/audit allows one repair; a second failure returns an error and preserves the reading. Structurally valid drafts repair only the rejected indices, preserve other items, and reject removal of every item. Previously approved identical observation/quotation checks may be reused only within that report invocation; full-source review always runs again. Process failures/tool activity are never replayed. The audit is still model-based and does not certify factual truth. Preparation makes one extraction call, one conditional-check call per eight evaluative requirements (up to two concurrently), and one whole-posting audit call, all inside the existing 180-second preparation deadline. No item is intentionally dropped to meet the capacity ceiling. Other-kind context is preserved without becoming a skill deficit or a claim about whether another document was submitted. Reports make a writer call, up to twelve separate citation checks (at most two concurrently), and a full-source check; repair may add calls, so a fixed two-to-four-call estimate is no longer valid. Offline effort comparisons can instantiate `CodexReasoner` with low/medium/high; serving remains low.

The `skip_host_skill_discovery` CLI feature is currently marked under development. Its startup warning is suppressed **only for this invocation**, with no global config change. A CLI upgrade requires another tool-isolation/structured-output smoke test. The code does not silently accept arbitrary tool-event output.

## Training and evaluation

`src/services/readme-lab/python/train.py` performs supervised **decision-head** training, freezing the encoder. It is not causal-language-model LoRA training. It validates labels, refuses group leakage between training/validation, checks token truncation, saves a head checkpoint and verifies reload predictions. Ordinary training requires `approved_by` per row; old unreviewed seed examples are not automatically approved. CLI summaries and user uploads are never added to a training set.

```sh
.local/readme-laya/venv/bin/python src/services/readme-lab/python/train.py \
  --model .local/readme-laya/model --data test/fixtures/readme/laya-smoke.jsonl \
  --out .local/readme-laya/training-smoke-new --steps 12 --smoke
pnpm exec tsx src/services/readme-lab/tools/smoke.ts
pnpm exec tsx src/services/readme-lab/tools/smoke.ts --fixtures
```

`--smoke` accepts only explicitly synthetic plumbing-test data. Its small diagnostic accuracy is not a product evaluation. Artifacts are under ignored `.local/`; the serving runtime keeps using the verified base checkpoint. Promotion requires a separately reviewed, representative Korean resume dataset, group-disjoint evaluation, question-resolution error analysis and calibration. No trained head is automatically activated.

The additional offline `python/experiment.py` supports four split synthetic experiments, randomized choice order, dev checkpoint selection, calibration-only temperature fitting, and optional last encoder layers. Its adapters are never loaded by the service. See [actual training experiments](readme-laya-training-2026-10-04.md) for data limitations and measurements. Both trainers now share runtime head/state token checks; the original trainer also rejects identical content across splits and remaps SDK option-order targets.

`tools/reader-quality-eval.ts` runs the actual v2 relation heads and the offline Codex same-prefix baseline on `test/fixtures/readme/reader-prefix-cases.json`, then compares v1/v2 final source review on the same document. It requires an unused output directory, marks labels provisional and human_reviewed=false, and records all answers. Do not promote these observed development cases to a held-out accuracy claim. See [label policy](readme-label-policy.md) and [implementation evidence](readme-quality-implementation-2026-10-04.md).

## Claude fixture handoff

`docs/fixtures/readme-lab/short.json`, `long.json`, `partial-failure.json` each contain `{synthetic:true,fixture:true,authored:true,prepare,snapshots,final}`. These are hand-authored, deterministic UI fixtures, not measured model outputs. Short: three sentences; long: forty sentences across eight blocks with eleven notes, five questions, six distinct report items; failure: the third sentence fails after two completed windows. The source is `tools/design-fixtures.ts`; `smoke.ts --fixtures` regenerates it without any model call. Current fixtures preserve v1 held semantics; they do not demonstrate validated question resolution. Replay snapshots' events at a comfortable UI pace. The prepare payload includes the same document used by note/report citations. `prepare-empty-requirements.json` covers an empty requirements result; oversized documents fail instead of supplying a truncated reading.

Real smoke execution honors the same `README_CODEX_BIN` and `README_CODEX_MODEL` variables as the service and prints the selected binary path in its synthetic summary. The default is `/opt/homebrew/bin/codex`, independent of PATH. When overriding, verify login/version using that same absolute binary. Shell and launchd PATHs may differ; no launchd configuration was changed here.

`v2-transitions.json` is an additional hand-authored fixture for question → partial → resolved → reopened, permanent source annotations, connector events and replay. It is not a base-model result. Generate with the same `--fixtures` command. Use `smoke.ts --out=.local/readme-laya/a-new-run.json` to preserve earlier measured runs.
