# Jev 문맥 연결 재판정과 응답 오류 복구 검증

2026-10-05. 합성 문서로 확인한 내부 구현 기록. 사람 검토를 거친 일반 정확도, 고용24 연계, 학습 완료, 공개 배포를 뜻하지 않는다.

## 구현

- 기본 grounded v21의 판단 기준과 모든 .75 임계값을 유지한다. Reader v6는 아직 해소되지 않은 본인 역할 질문에서 실제 수행으로 보이는 문장이 있을 때만 추가 문맥 확인을 요청한다. 후보 검색은 근거 채택과 분리한다.
- Codex는 현재까지 읽은 원문만으로 구체 업무, 행위자, 계획/실제 수행, 업무명 근거와 수행 근거를 구조화한다. 별도 검토가 같은 경험·같은 업무·본인 실제 수행·철회되지 않음·선택한 인용의 충분성을 모두 승인해야 답으로 채택한다. 계획 A와 완료한 다른 B, 담당 예정과 수행자 불명의 완료를 합치지 않는다.
- 채택한 정확한 원문은 Python의 기존 adopted 기록으로 들어간다. 업무 연결 정보도 같은 질문에 보존한다. 이후 정정은 기존 근거 재검사로 질문을 다시 연다. TS에서 리포트만 따로 바꾸거나 과거 읽기 기록을 소급 변경하지 않는다.
- 추가 확인은 문서당 최대 2회, 각 회당 제안·검토 최대 2개의 CLI 요청이다. 제안과 검토를 합해 40초 제한을 적용하며 자동 CLI 재시도/초안 수리는 없다. 해당 기능을 사용하는 worker step은 최대 90초, 전체 기존 10분 제한은 유지한다. 호출 실패·판단 보류도 횟수를 소비한다.
- worker와 부모는 현재 요청 ID·질문·현재 구간·순차 nonce를 대조한다. 부모가 보관한 원문으로 입력을 재구성하고 정확한 전체 구간 인용만 허용한다. 취소는 Python worker와 Codex에 전달된다.

## 제공자 오류 처리

확률 분포 검증을 유지한다. 선택 답/최댓값 불일치와 분포 합 오류, HTTP 502/503/504에 한해 같은 요청 전체를 한 번 재시도한다. 문서 전체 재시도는 최대 2번이다. 서로 다른 응답의 일부 답을 섞거나 선택 답을 임의로 고치지 않는다. 인증·모델·키·타임아웃 등의 오류는 이 규칙으로 재시도하지 않는다.

모든 물리 요청과 실패 응답에서 확인 가능한 사용량을 예산에 반영한다. 실패 응답에 사용량이 없는 경우 실제 청구량을 완전히 알 수는 없다. 사용자 원문·키·제공자 본문을 오류 로그에 싣지 않고 고정 오류 코드와 호출 번호만 전달한다. 실패한 step의 근거 채택·질문별 캐시 등 의미 상태는 되돌리되 사용량과 복구 시도 횟수는 되돌리지 않는다.

지속적인 제공자 실패는 기존 `failed + partial` 계약으로 끝난다. 앞서 확정한 결과는 유지하고 정상 완료 리포트를 만들지 않는다. **실패 구간만 건너뛰고 전체를 완료시키는 기능은 구현하지 않았다.** 별도의 화면 상태 합의 없이 불완전한 독해를 정상 완료로 표시하지 않기 위해서다.

선택적인 Codex 문맥 확인만 실패한 경우에는 유효한 Jev 결과를 유지한다. 이 실패는 내부 기록과 기존 리포트 한계 문구에 따로 전달하며, 문서에 설명이 없다는 근거로 취급하지 않는다.
