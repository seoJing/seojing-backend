# README 판단 품질 개선 · 구현과 실측

2026-10-04 KST. `codex/readme-laya-runtime`, 기준 HEAD `060aef8d4c2c3fdce9fcb2e9fcaf0b6c2ff43413` 위의 미커밋 작업이다. 이전 구현을 보존했다. 공고 기준·순차 상태·리포트 검증을 구현했고, 실제 합성 입력으로 최종 리포트의 근거 회수를 확인했다. **기본 Laya의 독해 품질은 아직 미달이며 파인튜닝·배포 완료가 아니다.**

## 적용한 변경

1. 공고 원문에서 요건 추출 → 조건부 독해 기준 작성 → 의미 검토의 세 단계로 준비한다. 각 기준에 질문을 시작할 조건, 충분한 설명, 부족한 반례를 둔다. 원문 요건을 참조하지 못하거나 의미 검토가 실패하면 입력 준비를 실패로 끝낸다. 지원자 원문으로 채용 기준을 바꾸지 않는다.
2. 이미 읽은 원문 전체와 질문 이력을 서버 장부에 남긴다. 같은 scope의 앞선 설명을 먼저 참고하고, 실제 토큰 한도를 넘을 때만 축약한다. 축약 때문에 보이지 않는 내용을 누락으로 단정하지 않는다. 모든 기존 질문과 현재 문장을 비교하므로 질문이 9개 이상이어도 한 번만 등장한 답을 건너뛰지 않는다.
3. Laya 판단을 주체·실제/계획·역할/방법/결과/근거·요건 관련성·질문 조건·질문과 후속 문장의 관계로 나눴다. 새 head의 선택지와 학습 데이터 검증기를 추가했으며, 가중치는 바꾸지 않았다. 선택값은 [v2 구현 범위](readme-reader-v2.md)에 명시했다.
4. 원래 질문을 유지하며 버전이 있는 불변 `question_updated` 이벤트를 보낸다. 마지막까지 open인 질문은 open_at_end 이벤트로 끝낸다. 기본 모델의 답 후보는 held까지만 허용한다. partial/resolved/reopened는 검증기 주입 테스트와 수동 시안으로 확인했고 실제 서비스 검증기는 활성화하지 않았다.
5. 최종 Codex 리포트에는 메모가 없는 문장도 포함해 제한 내 전체 원문을 제공한다. 원문 인용·메모 연결·요건 참조를 검증한 뒤 별도 모델 호출로 주체/시점/경험/수량/인과/누락 주장/질문 상태/요건 의미를 검토한다. 실패한 초안은 한 번만 재작성하며 재실패는 오류로 남긴다. 모델 의미 검토는 사실 인증이 아니다.
6. 브라우저 상태 어댑터, v2 전이 시안, 같은 prefix에서 Laya/Codex를 비교하는 도구, 사람이 검수할 라벨 정책을 제공했다. 메모/인용/질문 표시 외의 프론트 디자인은 수정하지 않았다.

## 재현 자료

저장소 루트 기준이며 `.local/` 자료는 로컬 측정 기록으로 Git에 포함되지 않는다. 실제 사용자 자료를 이 경로에 기록하도록 바꾸지 않는다.

- `.local/readme-laya/reader-v2-eval-20261004/run.json`: 사례별 입력·선택·시간·모델 메타데이터. 데이터 SHA256 `65f703059f3e8e31cbadf7517a48229fff6928ac44cb0eeef58a204d90ca6f73`.
- 같은 디렉터리 `report-comparison.json`: 같은 원문의 v1/v2 리포트 비교. 최초 v2 문구 결함도 보존.
- `.local/readme-laya/report-v2-recheck.json`: 문구 검증 추가 후 실제 리포트 재실행.
- `.local/readme-laya/e2e-v2-short.json`, `e2e-v2-long.json`: 실제 prepare/폴링/전체 이벤트/최종 리포트와 시간. 같은 이름의 `.log`에 요약.
- `.local/readme-laya/v2-head-smoke.log`: 새 head의 명확한 문장에 대한 낮은/잘못된 선택 예. 기본 모델이 새 과제를 해결한다고 가정하지 않은 근거.

## 검증과 인계

독립 읽기 전용 검토에서 발견한 과거 문맥의 조기 축약, 8개 질문 순환 검사의 비교 누락, 시안 메모/인용 불일치를 수정하고 회귀 테스트를 추가했다. 검토자는 9번째 질문의 답 후보가 유지되는지와 v2 시안이 실제 리포트 검증기를 통과하는지 재현해 수정 후 추가 결함을 찾지 못했다. 모델 품질 승인이나 배포 승인은 아니다.

최종 검사: typecheck, lint, format:check, build 모두 통과. Vitest **137개 통과 / DB 의존 6개 생략**, Python 데이터 검증 **5개 통과**, `git diff --check` 통과. 빌드는 운영 dist를 덮어쓰지 않고 `.local/readme-lab-build`에 생성했다. 로그는 `.local/readme-laya/v2-final-{typecheck,lint,format,build,test,python}.log`, 좁은 회귀 검사는 `v2-review-regressions.log`의 22개 통과다. 마지막 변경은 이 문서의 결과 기록뿐이며 별도로 포맷을 확인했다.

Claude에는 `contracts.ts`와 `browser-client.ts`, `docs/fixtures/readme-lab/v2-transitions.json`, [HTTP/화면 계약](readme-lab.md)을 함께 전달한다. 이벤트의 원래 질문 위치·현재 근거·이전/새 상태로 연결선을 그리며, policy v1의 held는 해소로 승격하지 않는다. 시안의 모델명은 수동 작성임을 표시한다. 리포트는 메모 없는 원문을 인용할 수 있어 `note_ids=[]`를 허용한다.

v2 활성화 전 동의 문구는 전체 추출 텍스트가 Codex 클라우드로 전송됨을 설명해야 한다. 기존의 메모만 전송한다는 문구로 사용하면 안 된다. 실제 서비스에서 Codex가 질문 전이를 검증하는 추가 경로와 `generation.decision_verifier` 표시는 board decision `8e5f7c`에 제안했지만 승인·구현되지 않았으며, 이번 오프라인 비교와 구분한다.

## 다음 품질 단계

먼저 [라벨 정책](readme-label-policy.md)에 따라 약 30개 기준 prefix를 사람이 검수해 질문의 의미와 complete/partial/conflict 경계를 고정한다. 그다음 경험·공고·템플릿 그룹을 나눈 학습/검증/보정/평가 자료로 Laya head 학습을 진행한다. 생성 라벨이나 이번 코드 리뷰를 사람 승인으로 위장하지 않는다. 불필요한 질문, 잘못된 해소, 답 발견률, 보류율, 인용 정확도, 지연을 각각 측정하고 기본 모델과 비교한 뒤 승격한다.

즉시 해소 장면이 필요한 시제품에는 오프라인에서 시험한 Codex 검증 경로가 후보이나, 호출 시간과 클라우드 처리 고지를 포함해 별도 계약·평가가 필요하다. 이번 구현은 판단을 기록하고 검사할 기반과 리포트 입력의 실제 결함을 개선한 단계다. 본학습, 확률 보정, 대표 데이터 성능, 프론트 연결, Work24 외부 연동, 운영 배포는 완료하지 않았다.
