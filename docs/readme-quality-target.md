# 지인용 README 독해 품질 목표

2026-10-04. 사용자가 목표 품질까지 개선을 계속하도록 요청한 작업의 통과 기준이다. 현재 목표는 **출처를 확인할 수 있고 실제 수정에 도움이 되는 순차 독해 시제품**이다. 인간 채용담당자의 판단·합격 가능성·모든 이력서에 대한 정확도를 인증하지 않는다.

## 고정한 통과 조건

1. 입력 경계: 모델 호출마다 현재 문장과 이미 읽은 원문만 제공한다. 미래 문장 교체가 이전 입력·기록을 바꾸지 않는 회귀 검사를 통과한다. 원문 인용·UTF-16 범위·요건·질문 ID는 100% 유효해야 한다.
2. 독해 행동: 최소 24개 새 합성 시나리오에서 질문 생성·부분 설명·해소·재확인·중복 방지의 명세 검사를 90% 이상 통과한다. 명확하게 답한 사례의 해소 탐지는 90% 이상이어야 한다. 모두 보류하는 모델은 통과하지 않는다.
3. 중요한 오류: 팀→개인, 계획→수행, 다른 경험 연결, 부정 반전, 근거 없는 해소·원문 조작·문서 내 지시 실행은 시험군에서 0건이어야 한다. 이는 시험에서 관찰하지 않았다는 뜻이며 실제 오류 확률 0의 보장은 아니다.
4. 일반화 점검: 개선에 사용하지 않은 추가 8개 표현/상황 시나리오를 마지막에 검증한다. 같은 사례에 맞춰 프롬프트를 고친 결과와 새 사례 결과를 따로 기록한다. 실패 후 수정했다면 그 시험군을 새 비공개 평가라고 다시 부르지 않는다.
5. 리포트: 최소 6개 다양한 전체 흐름에서 실제 CLI 리포트를 생성한다. 인용·원래 질문 이력·후속 정정이 일치하고, 이미 있는 설명을 다시 요구하거나 없는 경험을 쓰게 하는 항목이 없어야 한다. 읽기 전용 독립 검토와 자동 검사를 함께 사용한다.
6. 구현: 상태 이벤트 불변성, 재수신, 취소/타임아웃/부분 실패, 입력 검증, 기존 기능 회귀를 검사하고 저장소 lint/typecheck/format/build/test를 통과한다.
7. 사용성: 단계마다 진행 상태가 보이고 최초 유용한 독해 응답과 전체 시간을 실제 측정한다. 초기 목표는 문장당 p95 30초 이하, 12문장 읽기+리포트 6분 이하이다. 개발 평가에서 최소 30회 실제 호출을 측정하되 대규모 서비스 p95로 확대하지 않는다. 넘으면 호출 수·검증 배치를 줄이되 미래 정보나 검증을 숨기지 않는다.

## 평가 경계

위 자료는 출처와 예상 동작이 분명한 합성 사례이며 사람 검수 정답셋이 아니다. 시나리오 명세는 생성 모델과 별도로 고정하고 독립 검토로 모순을 찾는다. 숫자는 개발 행동 시험의 통과율로 보고한다. 실제 문서의 주관적인 유용성은 지인 시험에서 추가 확인해야 하며 그 결과를 미리 만들지 않는다.

Codex CLI로 순차 독해 기준선을 먼저 만든다. Laya는 통과한 작은 판단부터 별도 비교로 대체할 수 있지만, 현재 실험용 가중치를 자동 승격하지 않는다. 공개 응답의 엔진/처리 위치는 사실대로 표시하고, 원문이 클라우드로 전송되는 범위를 고지한다. 모델이 정상 동작하는 시제품을 만드는 일과 운영 배포 승인은 분리한다.

공식 문서 확인: [Codex 비대화형 실행](https://learn.chatgpt.com/docs/non-interactive-mode), [관찰 가능한 동작을 검사하는 평가 예](https://developers.openai.com/blog/eval-skills). 기존 ChatGPT 로그인 CLI와 JSON schema 출력을 사용하며 API 키를 추가하지 않는다.
