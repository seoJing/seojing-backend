# Jev 원문 근거 판단 개선 — 2026-10-04

Jev를 선택한 뒤 내부 실험 엔진 `jev-grounded-v8`을 구현했다. 기존 39개 개발 사례에서 보완 필요 판정을 채택한 수는 이전 atomic Jev의 **1/17 → 12/17**로 늘었다. v8 개발 사례의 채택 31개에는 잠정 라벨과 다른 판정이 없었다. 하지만 새 16개 사례에서는 **12/16 일치, 채택 11개·라벨 오류 0개, 보류 5개**였고, 44개 문장 순차 시험은 **11/15 확인 지점 통과**다. 일반 사용 품질 목표 달성이나 서비스 전환 완료를 의미하지 않는다.

모든 문서와 정답은 에이전트가 작성한 합성 자료다. 사람의 채점, 실제 이력서, 채용 성과와의 상관관계는 검증하지 않았다. confidence 0.75는 유지한 행동 기준이며 정확도 75%라는 뜻이 아니다.

## 구현한 판단 과정

1. 질문을 개인 역할 또는 수치 근거로 제한한다. 역할은 본인·실제 수행·구체적 행동, 수치 근거는 전·후 값·측정 방법·비교 가능성을 각각 묻는다.
2. 현재까지 읽은 원문만 사용한다. 각 후보 문장이 같은 경험과 질문을 설명하는지 확인한다. 직전 두 문장을 함께 보내 지시어를 해석한다. 미래 문장, 기대 라벨, 평가용 메타데이터는 모델 입력에서 제외한다.
3. 원문 × 조건을 독립적으로 확인한다. 여러 유효한 근거가 선택지 하나를 놓고 경쟁하지 않게 한다. 원문을 질문에 직접 포함하고, 과거의 가정·다른 사람·다른 경험·철회 조건을 놓치지 않도록 **전체 원문 prefix**를 문맥으로 보존한다. 필터는 근거 후보를 줄일 뿐 전체 문맥을 삭제하지 않는다.
4. 모든 조건을 뒷받침하는 후보가 있으면, 후보 자체의 완전성과 전체 문맥에서의 유효성을 별도 질문으로 확인한다. 둘 다 통과한 정확한 원문만 `evidence`로 반환한다. 철회된 옛 주장이 진단용 `facts`에 남아 있어도 승인 근거에 포함하지 않는다. 두 확인은 같은 Jev의 교차 확인이며 독립된 정답 판정자가 아니다.
5. 철회는 과거에 실제로 존재했고 현재 직전까지 유효했던 필수 근거를 새로 부정하는지 확인한다. 최초 비수행 설명, 단순 역할 구체화, 이미 철회한 내용의 반복은 새 철회와 구분한다. 이 구분은 아직 실제 모델 오판이 남아 있다.
6. 순차 reader는 마지막으로 채택한 근거를 기억한다. 해소 상태에서 관련·불확실한 새 문장이 나오면 그 정확한 근거를 전체 원문으로 다시 감사한다. 놓쳤던 철회가 뒤늦게 확인돼도 다시 열 수 있다. 불확실한 감사는 `uncertain_update`를 남긴다.
7. 보완 피드백은 원문과 확인 조건에 연결한다. “적지 않았다”를 “하지 않았다”로 바꾸지 않는다. 원인이 불확실해도 확인이 필요한 구체적 조건을 표시한다. 계획·예시, 타인 업무, 비교 조건 차이를 실제 능력 부족으로 바꾸지 않는다.

현재 지원하는 두 facet 이외의 공고 기준, 자동 질문 생성, 순위·점수 산출은 이 모듈이 구현하지 않는다. 각 reader는 최대 호출 수와 선택 근거 수를 제한한다. 필터 캐시는 질문·원문·직전 문맥·선택지 순서가 같은 경우에만 재사용한다. 원문을 임의로 자르는 대신 한도를 넘으면 보류한다.

현재는 내부 실험 모듈이며 기존 HTTP serving과 프론트 계약을 전환하지 않았다. Jev 결과를 Laya로 표시하지 않는다. 2026-10-04 API-03 결정 게시물 `6cc9a9`에 기존 화면 데이터 형태를 유지하면서 `generation.engine=jev`, 고정 원격 모델 정보, 준비·리포트의 `codex_cli` 출처를 구분하는 제안을 올렸다. 공유 계약 변경은 상대 작업자의 확인 후 적용한다. Claude 소유 경로는 수정하지 않았다.

다음 판단 기준은 사람의 실제 문서 평가와, 자동 질문 생성부터 Codex CLI 최종 리포트까지 한 번에 측정한 품질·시간이다. 먼저 현재 보류·중복 철회·해소 지연을 고정 회귀 사례로 유지하고, 별도의 새 자료와 사람의 채점에서 거짓 해소·불필요한 보완 요구·피드백 유용성을 검증해야 한다. 현재 숫자로 일반 이력서 정확도나 실사용 준비 완료를 주장하지 않는다.

Jev는 고객별 fine-tuning 대신 질문·판단 기준·state를 통해 조정하는 모델이다. 이번 작업은 모델 학습이나 Laya fine-tuning이 아니다. [공식 커스터마이징 설명](https://docs.typesafe.ai/models), [confidence의 정의](https://docs.typesafe.ai/confidence)
