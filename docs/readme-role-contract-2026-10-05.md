# 역할 설명과 판단 기준 개선

2026-10-05. 적용·검증 기록. 전체 품질 목표와 공개 준비 완료를 뜻하지 않는다. API-03, 백엔드 내부 변경이며 공개 이벤트 계약은 유지한다.

## 판단 계약

역할 질문은 같은 경험에서 지원자 본인이 실제 수행한 구체적인 업무가 한 가지 이상 적혀 있으면 해소한다. 업무 방법의 깊이, 성과 수치, 공고에 나열된 모든 업무의 수행은 이 질문의 해소 조건이 아니다. 공고 조건은 질문의 관련성을 결정하며, 개인 역할을 확인한 사실이 모든 자격을 충족한다는 뜻은 아니다.

본인·실제 수행·구체 업무는 같은 행동에 묶여 있어야 한다. 본인의 추상적인 참여와 동료의 구체 업무, 본인이 수행한 추상 업무와 미래의 구체 계획을 합쳐 해소하지 않는다. 정확한 원문 근거에 긍정 설명이 있어야 하며 전체 prefix는 대명사·경험 연결과 가상/계획/철회 문맥을 확인하는 데 사용한다.

부정과 보류를 구분한다. unknown은 뜻이나 근거 연결을 확정하지 못한 경우이며 부족함이나 무능력을 뜻하지 않는다. 개발 자료에서 안전한 보류를 허용하는 음성 사례는 exact-label accuracy로 보고하지 않는다. 긍정 해소 탐지, 잘못된 해소, 보류, 철회 유지 여부를 따로 기록한다.

## 평가 계획과 제한

변경 전 v16 소스와 24개 새 개발 사례를 먼저 고정했다. 원래 문제를 재현한 두 실제 프로파일 합성 사례 및 경험 혼동 회귀 사례도 유지한다. 추가 미사용 사례는 독립 에이전트가 작성하며, 사람 검수 정답은 아니다.

확신도는 정답 확률이 아니다. 역할 행동 결합, 경험 연결, 원문 사실, 유효성, 철회, 성과 근거, 누락 사유의 판단 기준을 별도 이름으로 관리하고 평가 도구에서만 개별 값을 실험한다. 운영 기준을 낮추려면 별도 근거가 필요하며, 이번 시험 결과를 일반적인 정확도 보정으로 부르지 않는다.

## 적용한 구현: grounded v21 / reader v5

- 생성된 공고별 충분 조건이 역할 질문에 방법·성과·모든 업무 수행을 추가하지 않도록 역할 설명 계약을 고정했다. 공고 관련성 판단과 공개 질문 계약은 유지한다.
- 원문별 본인·실제 수행·구체 업무 확인 뒤, 정확한 제시 근거에서 같은 행동의 결합을 확인한다. 마지막 검사는 해당 근거를 무효화하는 가상/타인/다른 경험/철회 문맥이 있는지로 한정한다. 반박이 없다는 사실만으로 해소할 수 없고, 모든 긍정 조건과 행동 결합도 통과해야 한다.
- 역할 결합이 거절되거나 불확실할 때 여러 사람의 사실 조각을 partial 근거로 채택하지 않는다. 실제 철회 검사는 이 차단보다 먼저 처리된다. 독립 검토에서 발견해 회귀 검사를 강화했다.
  ₩기준을 내부 정책으로 분리했다. 모두 기존 0.75를 유지하며 API/환경 변수로 변경할 수 없다. 평가 CLI의 `--threshold=role_binding=0.70`처럼 한 판단만 변경해 비교할 수 있다.

## 개발 비교

모두 원문과 소스를 고정한 합성 개발 실험이다. v16과 v21의 새 개발 24개는 긍정 12개 모두 해소, 나머지 12개에서 잘못된 해소 0건이다. v16의 부정군 보류 7개가 v21에서는 6개이며, partial로 분류된 부정군에는 긍정 근거가 없어서 실제 reader에 채택되지 않는다. 허용 결과 일치 24/24를 일반 정확도라고 부르지 않는다.

기존 실제 프로파일 재현 2개는 이전 v16 기준선 1/2에서 v21 2/2로 바뀌었고, 선택지 순서를 뒤집어도 2/2다. 경험/성과 회귀 8개는 8/8, 기존 인접 역할 회귀 8개는 허용 결과 8/8이다. 짧은 센터/축제 근거 혼동은 여전히 unknown이며, 기대한 unrelated 정답은 아니지만 타 경험 근거를 채택하지 않는다.

v20 개발 실험에서 역할 결합 기준을 0.70 / 0.75 / 0.85로 바꿔도 긍정 12/12와 잘못된 해소 0건은 동일했다. 따라서 낮은 기준을 도입할 근거가 없다. 이는 역할 결합 기준만 비교한 것이며 다른 판단의 최적 기준이나 정답 확률 보정은 수행하지 않았다. v21은 v20의 결합 실패 후 partial 채택을 차단한 버전이다.

## 미사용 자료의 첫 검증과 한계

독립 에이전트가 작성한 8개 시나리오를 처음 실행한 v21 결과는 **엄격한 라벨 12/15, 상태 14/16**이다. 본인 업무 확인·철회·다른 업무로 회복·다른 고객 분리·실습과 실무 구분·날짜 정정은 통과했다. 두 실패는 계획 후 실제 수행의 경험 연결과, 앞선 계획의 업무명을 뒤의 ‘이 작업’에 연결하는 사례다. 계획만 있는 문장을 partial 대신 unknown으로 보류한 라벨 실패도 따로 기록했다. 원문 인용은 모두 유효하며 잘못된 해소나 재개방은 관찰하지 않았다. 이 결과를 전체 품질 목표 통과로 해석할 수 없다.

이 8개는 결과를 보고 추가 실험에 사용했으므로 이제 개발 자료다. v22는 시간 흐름 정책과 개별 사실 질문을 보완했고, v23은 지시어의 앞선 근거와 최종 경험 확인을 추가했지만 **상태는 모두 14/16 그대로**이다. 엄격한 라벨은 12/15에서 13/15로 한 개 개선됐지만 실제 해소 상태는 나아지지 않았다. 호출은 v21/v22/v23 각각 53/53/57회, 입력 토큰은 72,683/79,751/94,322개다. 두 변경은 적용하지 않았으며 최종 서비스 소스는 검증한 v21과 해시가 같다. 신규 6개 시나리오는 별도로 고정했으며 최종 검증 결과를 아래에 기록한다.

## 최종 전체 흐름 검증

같은 합성 문서와 공고의 고정된 준비 결과를 사용해 독해와 Codex 리포트를 새로 실행했다. 두 흐름은 순차 실행하며 프롬프트나 서비스 소스를 중간에 바꾸지 않는다. 업로드 파서·공고 추출·HTTP 큐·브라우저를 포함한 측정은 아니다.

- 긴 문서 본문 50문장·제목 5개, 총 55개 구간: 총 **248.417초**, 독해 **89.960초**. ## 추가 6개 전이 시나리오

새 6개를 처음 실행한 `jev-role-contract-transfer-heldout-v21-final`은 마지막 호텔 사례의 원문 사실 판단에서 `invalid_answer_distribution_argmax`로 중단됐다. 선택 답과 확률 분포가 일치하지 않는 제공자 응답을 받아 검증에 실패했으며, 실패·동결 입력·원시 판단 기록 29개를 보존했다. 일부 시나리오 진행 로그를 전체 성공으로 세지 않는다.

프롬프트·임계값·코드·데이터를 바꾸지 않고 별도 실행한 `jev-role-contract-transfer-v21-repeat1`은 완료했다. **상태 9/9, 엄격한 라벨 5/8**이다. 명확한 실제 업무 3개는 모두 해소됐고, 다른 계약·수행자 불명·계획한 A와 실제 완료한 다른 B를 잘못 해소하지 않았다. 과거 계획서를 나중에 인용해도 기존 해소를 철회하지 않았다. 라벨 실패 3개는 의미상 일부 설명이 있는 문장을 unknown으로 보류한 경우다. 이는 안전하게 상태를 유지한 것이지만 설명과 피드백을 충분히 제공한 성공으로 계산하지 않는다.

재실행은 새로운 미사용 평가가 아니며, 첫 제공자 실패도 지우지 않는다. 실행은 8.835초, Jev 39회이며 초기 trigger 6회를 제외한 Grounded 판단 33회가 journal에 있다. 기본 모델 응답의 불안정성과 계획→실제 수행의 놓친 연결이 남아 있으므로 **실사용 정확도·안정성 통과 또는 공개 가능 판정은 보류**한다.
