# README synthetic preview endpoint

`POST /readme/preview` accepts only `{"case_id":"social-program-operator"}`. The 256-byte body limit and explicit unknown-field check intentionally reject raw resume/job text. It is a no-store, stateless **rules-based synthetic preview**, not Laya inference and not Work24 integration. The response contains `mode`, `case_id`, `job` with source-quoted criteria, `resume.units`, sequential `events`, `report` with unit citations, and `limitations`. The frontend must display the mode and limitations.

This route can serve an interactive blog prototype while Python Laya training/service and Work24 data authorization are still pending. Do not infer model quality from its fixed synthetic trace. The separate user-file route below has its own transient-processing boundary; neither route implies model validation.

## Public user-file path

`POST /readme/analyze` accepts JSON `{job_text,resume_filename,resume_media_type,resume_base64}`. It supports UTF-8 TXT/MD, text PDF (first 10 pages), and DOCX. Binary file limit is 2,000,000 bytes; request body limit 3,000,000 bytes. PDF/DOCX magic and the **actual** DOCX ZIP expansion are checked; a lying central-directory size or hidden ZIP entry is rejected. A scanned image-only PDF has no OCR and yields a readable error. Parsing and rules run in a Node worker with a 12-second wall-clock limit and V8 heap limits; the parent also terminates an analysis if process-wide RSS grows by more than 512 MiB. DOCX expansion is independently bounded to 8 MiB by checking the complete ZIP directory and decompressed bytes. This is a bounded prototype, not an OS-level hard memory sandbox for pathological PDFs. The route caps two concurrent analyses and five requests/minute per Cloudflare visitor IP; the general public API rate limit also applies. Same-zone Worker subrequests preserve the visitor's `CF-Connecting-IP` when `x-real-ip` is not changed; the route trusts that header only over loopback tunnel ingress. Validate this assumption in deployed readback. No original file or extracted text is written to the service database or analytics, and no LLM/model call is made. Parsed text and report are returned to the requesting browser; the public proxy must not swap an upload failure for a synthetic report.

At most 120 ordered résumé units are analyzed; longer documents are truncated and labelled in `limitations`, not rejected outright. Extracted posting criteria are rule-selected candidates and shared keywords are not verified job fit. A fixed synthetic case is used for competition screens; user uploads are never used for that evidence.

This endpoint is independent of competition submission data. User documents must not be copied into the synthetic gold set, proposal screenshots, or fine-tuning examples. The service is still a rules-based preview, not real-time Laya inference. Cloudflare Worker forwarding and Mac mini ingress are separate network processors; avoid claiming the file never leaves the device.
